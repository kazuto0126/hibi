## 這個 App 是什麼

一款「用你自己的生活學日文」的手機 App。使用者把生活中的內容（一句日記、一張照片、一張截圖）丟進來，
AI 依使用者程度挑出適合學的日文單字、句子和文法，存成卡片，再用間隔重複排程複習；遇到問題可以隨時問 AI。

目標使用者：所有對日文學習有興趣的人，從零基礎到 N1。第一版以台灣、繁體中文使用者為主。

## 核心資料

- 使用者設定：程度（零基礎／會五十音／N5～N1）、學習目的（旅遊、考試、追劇動漫、工作，可複選）、興趣標籤 ✅
- 卡片：類型（單字／句子／文法）、日文、讀音、中文意思、例句、JLPT 級別、來源、建立時間、FSRS 複習狀態 ✅
  - 還沒有：來源原文、照片、建立地點（階段 6 會用到）
- 呼叫 AI 時要求回傳結構化 JSON，欄位對應卡片資料 ✅

## 內容規則

- 零基礎和會五十音的使用者，日文一律附假名與羅馬拼音 ✅（`src/core/romaji.ts`）
- N5～N4 的漢字附假名 ✅（複習卡翻面後顯示；初學者一開始就顯示）
- AI 給的讀音和意思可能出錯 △：內建詞庫已用 kuromoji 自動檢查；AI 產生的卡片還沒檢查，之後加入 JMdict 辭典比對
- App 不提供有版權的內容（歌詞、動漫字幕），只處理使用者自己輸入的內容 ✅

## 安全規則

原本的規劃：

- Gemini API 金鑰和任何密鑰都不能寫進 App 程式碼，也不能 commit 到 git；App 只呼叫我們自己的 Edge Function。
- 密鑰放在 .env 或 Supabase secrets，.env 必須加進 .gitignore。
- 所有使用者資料表都要開 Row Level Security，使用者只能讀寫自己的資料。

**目前的落差**：Hibi 還沒接後端，所以 v1 用「使用者自己申請金鑰、只存在自己手機」的過渡做法（不會寫進程式碼、不會進 git、備份也不匯出）。
自己用沒問題，但要給別人用，就要完成下面的階段 A，改回原本的規劃。

## 技術選擇的調整

| 原本規劃 | Hibi 的做法 | 理由 |
| --- | --- | --- |
| Expo Router 做頁面導覽 | 自己切換分頁 | 網頁 Demo 要打包成單一 HTML 放在 claude.ai，那裡不能用路徑式網址 |
| ts-fsrs 套件 | 自己實作 FSRS-6，ts-fsrs 只用在測試 | 讀懂演算法；用參考實作逐步比對，證明寫對 |
| Supabase 後端 | 規劃中（階段 A） | 舊專案已完成匿名登入與 profiles 資料表＋RLS，資料表定義搬到 `supabase/migrations/` |

## 下一步（每個階段開始前先提計畫，確認後再動手）

**階段 A：雲端同步與伺服器端 AI**
1. 建 Supabase 專案；沿用舊專案的匿名登入（publishable key 放 .env，靠 RLS 保護資料）
2. 資料表：profiles（已有）、cards、review_logs，全部開 RLS
3. Edge Function 代理 Gemini，金鑰放 Supabase secrets；App 改呼叫 Edge Function
4. 同步策略：手機上先存（離線也能用），有網路時再同步

**階段 B：拍照／截圖學**（階段 6）
- 選照片或截圖 → AI 抓出圖中日文、或說出物品的日文 → 勾選存卡；卡片附照片、時間、地點

**階段 C：漢字陷阱與字形對照**（階段 7）
- 建一份「同字不同義」清單（勉強、手紙、汽車、大丈夫……），卡片出現這些字時提醒
- 繁體與日文字形對照（圖書館／図書館）

**階段 D、E**：每日短文、生活日文覆蓋率（階段 8、9）
